# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **mise-managed dotfiles repository** for macOS. It captures live shell, editor, and CLI config from `$HOME` into git, and restores it onto a new machine. It previously used chezmoi; that is gone. Do not reintroduce `dot_` / `private_` / `executable_` prefixes, and do not suggest `chezmoi` commands.

The one mapping rule: **`home/` mirrors `$HOME` exactly.** The path under `home/` is the path under `$HOME`, no encoding. `home/.zshenv` → `~/.zshenv`; `home/.config/git/config` → `~/.config/git/config`.

Every dotfile is declared in `copy` mode, so restored files are real files, never symlinks into this repo.

## Commands

```shell
mise run ci          # lint + test (what CI runs)
mise run lint        # shellcheck scripts/*.sh scripts/lib/*.sh
mise run test        # bats tests/dotfiles.bats tests/config.bats
bats tests/dotfiles.bats               # run one suite
bats tests/dotfiles.bats -f "pattern"  # run tests matching a name

mise run dotfiles:backup    # capture live $HOME → repo (never writes $HOME)
mise run dotfiles:verify    # coverage/checksum/mode/safety checks
mise run dotfiles:restore   # preview restore; add --apply to write $HOME
mise run dotfiles:modes     # replay recorded modes after a restore
```

`./scripts/backup-dotfiles.sh ~/.zshenv` captures a single target. `./scripts/verify-dotfiles.sh --no-live` verifies the committed tree without a live `$HOME` (used in CI).

Requires `min_version = "2026.8.8"` of mise. Install via `curl https://mise.run | sh`, **not** `brew install mise` — homebrew-core lagged at 2026.7.15, on which reverse capture misbehaves. A fresh clone needs `mise trust` once before any `mise` command works.

## Architecture

The system has three coordinated data sources, all of which the verifier cross-checks:

1. **`mise.toml` `[dotfiles]` table** — the source of truth for *what* is managed and *where* it maps. Also holds `[bootstrap.packages]` (Homebrew formulae/casks) and the `dotfiles:*` / `lint` / `test` / `ci` repo tasks.
2. **`config/chezmoi-baseline.txt`** — the frozen coverage baseline (43 paths). The verifier's primary invariant: every baseline path must have a manifest row. `config/baseline-exclusions.tsv` records deliberate omissions.
3. **`config/dotfiles-manifest.tsv`** — authoritative *mode* record (`path<TAB>source<TAB>sha256<TAB>mode<TAB>size`). Git records only the executable bit and cannot carry `0600`, which ~half the managed files use — so modes come from here, not the checkout. Regenerated by backup; replayed by `dotfiles:modes`.

Scripts in `scripts/` share two sourced libraries in `scripts/lib/`:
- `common.sh` — logging, `die`, `require_command`.
- `dotfiles.sh` — repo paths, path validation, manifest generation, and the safety guards.

**The central safety hazard**: mise resolves the relative `dotfiles.root = "home"` against the *process working directory*, and its default (`~/.dotfiles`) writes into `$HOME`. So every script `cd`s to the repo root and calls `dotfiles_enter_repo`, which asserts the resolved root stays inside the repo before running mise. Backup always passes `--no-apply` (live → repo only, never touches `$HOME`), refuses symlinks, and refuses any target not already configured.

## Hard rules (enforced by verify-dotfiles.sh and the Bats suites)

- Every `[dotfiles]` entry states `mode = "copy"` explicitly. Never rely on `default_mode` — an entry mise writes itself omits `mode` and falls back to `symlink`.
- No `symlink` / `symlink-each` entry, ever.
- No directory entry on `~/.config`, `~/.config/mise`, or `~/.claude`: those trees hold untracked local files, including a secret in `~/.config/mise/config.local.toml`. Directory entries are allowed only where the live tree contains exactly the baseline files (`~/.warp/themes`, `~/bin` are per-file for this reason).
- Adding a dotfile is deliberately explicit: (1) add the `[dotfiles]` entry with `mode = "copy"`, (2) add the path to `config/chezmoi-baseline.txt`, (3) run `mise run dotfiles:backup`.
- Deployed mise tasks in `home/.config/mise/tasks/` must have the executable bit set in git (`100755`); there is no filename prefix conveying executability.

## Shell script conventions

`#!/usr/bin/env bash`; `set -euo pipefail` in executables (libraries omit it — they are sourced); tab indentation; a `# shellcheck source=` directive before each `source`; libraries guard double-sourcing with `readonly _<NAME>_SH_LOADED=1`. All scripts must be ShellCheck-clean.

## Testing

The Bats suites build an isolated `$HOME` inside `$BATS_TEST_TMPDIR` and **abort** if isolation fails, so they never touch real dotfiles. Overriding `HOME` alone is insufficient for mise — `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME`, and `XDG_STATE_HOME` must all be overridden (see `tests/test_helper.bash`). Never write a test that could reach the real `$HOME`.
